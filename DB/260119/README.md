
---

## 1. 데이터베이스 기본 개념

- **데이터베이스(Database)**  
  → 컴퓨터에 체계적으로 저장된 데이터의 집합

- **DBMS (Database Management System)**  
  → 데이터베이스를 관리하는 시스템  
  → 백업, 복구, 무결성, 동시 제어 등을 담당

- **파일 시스템 vs 데이터베이스**
  - 파일 시스템: 파이썬으로 직접 불러와야 하며, 데이터가 많아질수록 복잡
  - 데이터베이스: 대량 데이터 처리, 다중 사용자, 무결성 보장

---

## 2. 데이터 저장 구조

### 데이터 저장소 종류

- **데이터 레이크 (Data Lake)**  
  - 정형/비정형 원시 데이터를 그대로 저장  
  - 호수(lake) 개념

- **데이터 웨어하우스 (Data Warehouse)**  
  - 분석 목적에 맞게 정리된 데이터 저장소

- **데이터 마트 (Data Mart)**  
  - 웨어하우스 내부에서 특정 목적(의사결정 등)에 맞게 세분화된 저장소

---

## 3. 데이터베이스 종류

### 관계형 데이터베이스 (RDBMS)
- 데이터를 관계(Relation)로 표현
- 테이블 기반 구조
- 예: SQLite, MySQL, Oracle, MariaDB

#### SQLite 특징
- 임베디드 DB (설치/설정 간단)
- 하나의 파일에 테이블, 인덱스, 뷰, 트리거 포함
- 오픈소스
- 소규모 웹, IoT, 데이터 분석에 적합
- 현업 대규모 웹 서비스에서는 잘 사용되지 않음 (학습용)

---

### 계층형 데이터베이스
- 데이터가 종속 구조
- 레코드들이 링크로 연결

---

### 그래프 데이터베이스
- Node – Edge 구조
- 관계 중심 데이터 표현
- AI, 추천 시스템, 관계 분석에 활용
- 예: Neo4j
- RAG 구조에서 참조 DB로 사용

---

### NoSQL
- 관계형 모델을 벗어난 데이터베이스
- 예: MongoDB, Cassandra, Neo4j

---

## 4. 관계형 데이터 용어 정리

| 용어 | 의미 |
|---|---|
| 릴레이션(Relation) | 테이블 전체 |
| 튜플(Tuple) | 행(Row), 레코드 |
| 애트리뷰트(Attribute) | 열(Column), 필드 |

- 가로 = 튜플  
- 세로 = 애트리뷰트

---

## 5. 스프레드시트 vs 데이터베이스

| 스프레드시트 | 데이터베이스 |
|---|---|
| 소프트웨어 앱 | 질의 언어(SQL) |
| 행/열 단순 구조 | 관계형 구조 |
| 셀 단위 정보 | 컬렉션 단위 정보 |
| 데이터 제한 큼 | 대량 데이터 처리 |
| 수동 입력 | 엄격하고 일관된 입력 |
| 단일 사용자 | 다중 사용자 |
| 사용자 통제 | DBMS 통제 |

---

## 6. SQL 개념

- SQL은 데이터베이스를 다루는 언어
- 기계 중심 언어

### SQL 분류
- **DML**: SELECT, INSERT, UPDATE, DELETE
- **DDL**: CREATE, ALTER, DROP (SQLite는 TRUNCATE 없음)
- **DCL**: GRANT, REVOKE

---

## 7. SQLite 특이사항

- 날짜/시간 전용 자료형 없음
- TEXT로 저장
- decode 없음 → CASE WHEN 사용
- 날짜/시간 함수: strftime
- localtime → 현재 시간 기준

---

## 8. 정렬 · 집계 · 조건

- ORDER BY
  - 기본: 오름차순
  - DESC: 내림차순

- 집계 함수
  - COUNT, MAX, MIN, SUM, AVG, ROUND

- GROUP BY / HAVING
- 연산 우선순위: 비교 → 산술

---

## 9. JOIN & UNION

- JOIN: 관계 기반 결합 (조건절보다 권장)
- UNION: 중복 제거
- UNION ALL: 중복 포함

---

## 10. 기타 메모

- 테이블명은 단수형 권장 (Person)
- UNIQUE: 중복 불가
- LIKE, SUBSTR 등 문자열 처리 자주 사용
- SQL은 많이 써볼수록 익숙해짐

---

## 11. 오늘의 학습 포인트

- 쿼리작성에 집착하지 않고 개념 위주로 이해

- 통계 개념(OVER, 분산, 표준편차)은 추후 학습

## 조사 : 데이터베이스의 종류 (계층형, 관계형, 그래프형)


### 계층형 데이터베이스 (Hierarchical)
- 구조: 트리 형태(부모–자식)
- 장점: 구조가 단순하면 빠르고 관리가 쉬움
- 단점: M:N 관계 표현이 어렵고 구조 변경이 불편함

### 관계형 데이터베이스 (RDBMS)
- 구조: 테이블 기반, 키를 통한 관계 표현
- 장점: 정합성 관리가 뛰어나고 SQL 질의가 강력함
- 단점: 조인이 많아질수록 복잡해지고 비용 증가

### 그래프 데이터베이스 (Graph DB)
- 구조: 노드(Node)–엣지(Edge)
- 장점: 관계 탐색, 추천, 연결 분석에 매우 강함
- 단점: 표준 SQL 기반 분석에는 적합하지 않고 러닝커브 존재
