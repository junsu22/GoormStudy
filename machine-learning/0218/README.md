# 🤖 LLM 선행학습 ㅡ RAG 한식 레시피 챗봇 만들기


------------------------------------------------------------------------

## 🎯 오늘의 목표

-   RAG(Retrieval Augmented Generation) 구조 이해하기
-   LLM이 외부 데이터를 참고해 답변하도록 만들기
-   단순 챗봇 → **지식 기반 챗봇**으로 확장하기

이전 실습에서는 LLM API를 사용해 멀티턴 대화를 구현했다면,\
이번에는 텍스트 데이터를 직접 연결하여 **특정 지식을 기반으로 답변하는
챗봇**을 만들어보았다.

------------------------------------------------------------------------

## 📌 프로젝트 개요

  항목          내용
  ------------- -----------------------
  프로젝트      한식 레시피 RAG 챗봇
  LLM           LLaMA 3.3 70B
  플랫폼        Groq
  벡터 DB       FAISS
  임베딩 모델   ko-sroberta-multitask
  데이터        recipes.txt

------------------------------------------------------------------------

## 🧠 RAG란?

RAG(Retrieval Augmented Generation)는

> **LLM이 자체 지식만 사용하는 것이 아니라, 외부 문서를
> 검색(Retrieval)한 뒤 그 내용을 기반으로 답변(Generation)하는
> 구조**이다.

즉,

    질문 → 관련 문서 검색 → 문맥 전달 → LLM 답변 생성

LLM에게 새로운 지식을 "학습"시키는 것이 아니라,\
필요할 때 참고자료를 제공하는 방식이다.

------------------------------------------------------------------------

## ⚙️ 전체 동작 흐름

    recipes.txt 로드
    → 문서를 작은 조각(chunk)으로 분할
    → 임베딩 벡터 생성
    → FAISS 벡터 DB 저장
    → 질문 입력
    → 관련 문서 검색
    → LLM에게 context + 질문 전달
    → 답변 생성

------------------------------------------------------------------------

## 💻 핵심 코드 구조

``` python
loader = TextLoader("recipes.txt", encoding="utf-8")
documents = loader.load()

text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,
    chunk_overlap=50
)
chunks = text_splitter.split_documents(documents)

embeddings = HuggingFaceEmbeddings(
    model_name="jhgan/ko-sroberta-multitask"
)

vectorstore = FAISS.from_documents(chunks, embeddings)
retriever = vectorstore.as_retriever(search_kwargs={"k": 5})
```

문서를 벡터로 변환하여 의미 기반 검색이 가능하도록 만들었다.

------------------------------------------------------------------------

## 🧩 RAG 프롬프트 설계

이번 실습에서 가장 어려웠던 부분은 **프롬프트 제어**였다.

-   불필요한 인사 제거
-   지정된 형식으로만 답변
-   데이터에 없는 레시피는 거절
-   한국어만 사용하도록 제한

LLM이 자유롭게 말하지 않도록 규칙을 강하게 설정했다.

------------------------------------------------------------------------

## 🍳 데이터 예시

레시피 데이터는 txt 파일로 구성했다.

예:

    김치찌개
    재료: 김치 300g, 돼지고기 200g ...
    조리시간: 20분
    난이도: 쉬움

LLM은 이 데이터를 직접 학습하지 않고, 검색 결과를 참고해서 답변을
생성한다.

------------------------------------------------------------------------

## 🧪 테스트 결과

✔ 존재하는 메뉴 질문 → 정확한 레시피 출력\
✔ 없는 메뉴 질문 → 등록되지 않았다고 안내\
✔ 난이도 기반 질문 → 조건에 맞는 메뉴 추천

단순 생성형 모델보다 훨씬 안정적인 답변을 확인할 수 있었다.

------------------------------------------------------------------------

## 😅 시행착오

-   줄바꿈 형식이 계속 깨짐
-   불필요한 설명 추가됨
-   외국어가 섞여 출력됨
-   무료 API 크레딧 초과 (RateLimitError)

프롬프트만으로 해결되지 않아 후처리 필터(clean_japanese)도 추가했다.

------------------------------------------------------------------------

## 💡 오늘 배운 점

-   LLM은 데이터를 학습시키지 않아도 지식을 연결할 수 있다.
-   RAG의 핵심은 **검색 품질 + 프롬프트 설계**
-   챗봇 성능은 모델보다 데이터 구조에 크게 영향을 받는다.
-   실제 AI 서비스 구조와 매우 비슷한 흐름을 경험했다.

GPT-2 → API 챗봇 → RAG 구조까지 이어지면서,\
LLM이 단순 대화 모델이 아니라 **정보 시스템**이라는 느낌이 강하게
들었다.
