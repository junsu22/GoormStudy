# 프로젝트 전에 이해해본 AWS 기초 정리 (S3 중심)
프로젝트를 진행하기 전에 AWS가 정확히 무엇인지 감이 잡히지 않았다.\
이번 학습에서는 AWS 중에서도 **파일 저장을 담당하는 S3**를 중심으로,\
웹 서비스가 어떻게 구성되는지 큰 흐름을 이해하는 것을 목표로 정리했다.

------------------------------------------------------------------------

## 📦 S3 (Simple Storage Service)

### ✔ 개념

-   파일을 저장하는 클라우드 **객체(Object) 저장소**
-   서버 폴더 개념이 아닌 **Object Storage 구조**
-   사실상 용량 제한 없음
-   파일 수정이 아니라 **새 객체로 덮어쓰기(upload overwrite)** 방식

------------------------------------------------------------------------

### ✔ 왜 사용하는가

-   이미지 / 파일 저장
-   웹하드처럼 사용 가능
-   서버 디스크 용량을 사용하지 않아도 됨
-   파일 서버 부하 감소

------------------------------------------------------------------------

### ✔ 핵심 용어

#### Bucket

-   파일을 보관하는 저장 공간
-   전 세계에서 이름이 유일해야 함

#### Object

-   실제 파일
-   경로처럼 보이지만 key 문자열 구조

------------------------------------------------------------------------

### ✔ 접근 방식

#### Public Bucket

-   누구나 URL로 접근 가능

#### Private Bucket (권장)

-   인증된 요청만 접근 가능
-   보안성이 높음

------------------------------------------------------------------------

### ✔ Presigned URL (중요 ⭐)

-   일정 시간 동안만 접근 가능한 임시 URL
-   권한 없는 사용자도 제한 시간 동안 접근 가능

사용 목적: - 결제 사용자만 다운로드 허용 - 파일 직접 공개 방지

⚠️ Presigned URL은 클라이언트가 직접 생성하지 않고, **Backend 서버가 IAM
권한으로 생성 후 사용자에게 전달**한다.

추천 만료 시간: - 기본: 15분 - 큰 파일: 30\~60분

------------------------------------------------------------------------

### ✔ 권한 관리

-   Read: 공개 범위 신중히 설정
-   Write: 반드시 인증 사용자만 허용
-   IAM 정책 / Bucket 정책 사용

------------------------------------------------------------------------

### ✔ 비용 주의사항

-   저장 용량
-   다운로드 트래픽
-   요청 횟수

※ 실제 서비스에서는 RDS 비용이 가장 크게 나올 가능성이 있음

------------------------------------------------------------------------

### ✔ 실무 메모

-   버킷 이름 반드시 유일
-   프라이빗 + presigned URL 구조 권장
-   S3는 파일 서버가 아니라 **Object Storage**

------------------------------------------------------------------------

## 🔐 AWS 계정 설정

-   리전: Asia Pacific (Seoul)
-   프리티어 사용
-   MFA 반드시 등록
-   Root 계정은 서비스 개발에 사용하지 않음
-   인증앱: Microsoft Authenticator 가능

------------------------------------------------------------------------

## 📁 추가 개념 정리

### DRM (Digital Rights Management)

-   파일 접근 및 사용 권한 제어 기술
-   다운로드 제한, 접근 제어 가능
-   단점: 구현 비용 증가

------------------------------------------------------------------------

### 파일 변경 이력 / 라이프사이클 관리

-   오래된 파일 자동 삭제 또는 다른 스토리지 이동
-   S3 Lifecycle 정책 사용

------------------------------------------------------------------------

### Lambda Trigger (참고)

파일 업로드 시 Lambda 함수 자동 실행 가능

예: - 이미지 리사이징 - 메타데이터 처리

------------------------------------------------------------------------

### 정적 웹 호스팅

-   S3는 정적 웹사이트 호스팅 가능
-   무료 환경에서는 Vercel 사용이 편리

------------------------------------------------------------------------

## 🧱 서비스 구조 이해

기본 웹 서비스 구조:
```
Frontend (Vercel 등)
↓
Backend / API Server
↓
S3 (파일 저장)
↓
Database (RDS 등)
```
실제 업로드 흐름:

Frontend → Backend(API 요청)
→ Presigned URL 발급
→ Frontend가 S3에 직접 업로드

✔ 서버 트래픽 감소
✔ 파일 처리 부하 감소

------------------------------------------------------------------------

## 🌐 CORS (Cross-Origin Resource Sharing)

### 개념

프론트엔드 도메인과 S3 도메인이 다르면 브라우저가 요청을 차단한다.

### 왜 필요한가

브라우저의 **Same-Origin Policy** 보안 정책 때문이며, 서버 문제가 아니라
브라우저 정책 문제인 경우가 많다.

### 주의

-   설정 실수 시 디버깅 매우 어려움
-   업로드 실패의 주요 원인

------------------------------------------------------------------------

## 🪣 S3 버킷 생성 전 결정사항

### 접근 모드 선택

#### Private Bucket (권장)

-   presigned URL로 접근
-   보안성 높음

#### Public Bucket

-   영구 URL 접근 가능
-   읽기만 공개 권장

------------------------------------------------------------------------

### 버킷 설정 주의사항

-   버킷 이름: 전 세계 유일
-   길이: 3\~63자 권장
-   예: todo-dev-id
-   리전: 서울(ap-northeast-2)
-   Versioning: 초기 학습 단계에서는 비활성

------------------------------------------------------------------------

## 🔐 IAM (Identity and Access Management)

### IAM 사용자 생성

-   Root 계정 대신 IAM 사용자에게 권한 부여

### 최소 권한 원칙 (Principle of Least Privilege)

-   필요한 권한만 부여
-   Write 권한은 특히 제한

------------------------------------------------------------------------

## 🛡️ AWS 보안 모델

AWS는 공동 책임 모델을 따른다.

AWS 책임: - 인프라 보안 - 물리 서버 - 네트워크 기반

사용자 책임: - 접근 권한 관리 - 데이터 보호 - 설정 관리

------------------------------------------------------------------------

## 🌐 네트워크 개념

### VPC (Virtual Private Cloud)

-   AWS 내부의 개인 가상 네트워크
-   집 공유기처럼 내부망 분리
-   보안 격리 가능

------------------------------------------------------------------------

## 🔄 파일 업로드 흐름

Backend / EC2
↓ (Write 요청)
S3 Bucket
↓
Object 저장

------------------------------------------------------------------------

## ⚠ 트러블슈팅 메모

### Mixed Content 문제

-   HTTP와 HTTPS 혼합 시 브라우저 차단 발생

### 404 / 업로드 실패 원인 후보

-   CORS 설정 문제
-   인증 URL 만료
-   잘못된 endpoint
-   HTTPS 설정 문제

------------------------------------------------------------------------


### 🧠 학습 회고 메모

- AWS의 세부 기능을 모두 이해하기보다 전체 서비스 구조를 파악하는 데 집중했다.
- S3를 통해 클라우드에서 파일 저장이 어떻게 이루어지는지 큰 흐름을 이해할 수 있었다.
- 실제 프로젝트에서 필요해지는 시점에 맞춰, 필요하다면 추가 학습을 진행할 예정이다.
