

##  모델과 온디바이스

대형 LLM은 온디바이스 환경에 올리기 어렵다. 파라미터 수가 많고 메모리와
연산 자원을 많이 요구하기 때문이다.

반면 작은 모델은 로컬 환경에 올릴 수 있지만 성능이 제한적일 수 있다.
따라서 모델을 경량화하면서도 성능을 유지하는 최적화가 중요하다.

------------------------------------------------------------------------

##  NLP (자연어 처리)

자연어 처리는 사람이 사용하는 언어를 기계가 이해할 수 있도록 만드는
과정이다.

###   토크나이제이션 (Tokenization)

토크나이제이션은 텍스트를 문장 또는 단어 단위로 분리하는 과정이다.
기계는 문장을 그대로 이해하지 못하기 때문에, 어느 구간까지가 하나의
단위인지 나누어 주어야 한다.

결과는 일반적으로 리스트 형태로 저장된다.

공백이나 문장 부호를 기준으로 분리할 수 있지만, 단순 규칙만으로는 한계가
있다.

예: - 45.55 - Ph.D

이와 같은 경우 단순히 마침표를 기준으로 분리하면 본래 의미를 잃게 된다.
따라서 실제 토크나이저는 규칙 기반 알고리즘과 통계적 모델을 함께
사용한다.

상황에 맞는 전처리와 토크나이저 선택이 모델 성능에 영향을 준다.

###  Treebank Word Tokenizer

영어권에서 많이 사용하는 토크나이저이다.

-   하이픈으로 연결된 단어는 하나로 유지한다.
-   접어(contraction)는 분리한다. (예: don't → do + n't)

###  문장 단위 토큰화

온점, 느낌표, 물음표만으로 문장을 구분하면 오류가 발생할 수 있다.

예를 들어 Ph.D는 문장 끝이 아니다.

NLTK의 Sentence Tokenizer는 이러한 예외를 고려하여 동작한다. 한국어의
경우 KSS 패키지를 사용하는 것이 권장된다.

##  한국어 NLP의 어려움

영어보다 한국어 자연어 처리가 더 어렵다.

-   교착어 (조사, 어미 존재)
-   띄어쓰기 불완전
-   어순이 비교적 자유로움
-   주어 생략 가능
-   한자어로 의미가 달라질 수 있음
-   영어 대비 데이터 부족

예: 나는 체육관에서 운동을 했어
체육관에서 운동했어
나는 운동을 체육관에서 했어

표현은 다르지만 의미는 같다.

이러한 특성 때문에 형태소 분석기를 사용한다.

##  텍스트 전처리

###  Cleaning (정제)

불필요한 요소를 제거한다.

###  Normalization (정규화)

같은 의미를 하나로 통일하여 복잡도를 줄인다.

예: - 10, 159 → num - has, had → have - ㅋㅋㅋㅋㅋㅋ → ㅋㅋ

###  불용어 제거

자주 등장하지만 분석에 크게 기여하지 않는 단어를 제거한다.

단, 절대적인 기준은 없으며 데이터와 목적에 따라 달라진다.

###  정규표현식 활용

Apples, Apple, appels → apple\
ㅋㅋㅋㅋㅋㅋㅋㅋ → ㅋㅋ

중복을 줄이고 일관성을 유지하기 위함이다.

###  스펠 체커

맞춤법과 띄어쓰기 교정을 통해 데이터 품질을 높일 수 있다.

------------------------------------------------------------------------

##  정수 인코딩 (Integer Encoding)

토큰화된 단어에 고유한 정수를 부여한다.

예: 먹고 싶은 바나나\
→ \[4, 7, 5\]

중복은 허용하지 않는다.

------------------------------------------------------------------------

##  패딩 (Padding)

병렬 연산을 위해 문장의 길이를 맞춘다.

\[4, 7, 5\] → \[4, 7, 5, 0\]

------------------------------------------------------------------------

##  벡터라이제이션

텍스트를 숫자 벡터로 변환하는 과정이다.

###  원-핫 인코딩

특정 단어 위치만 1로 표시하는 방식이다.

한계: - 차원이 커진다. - 벡터 간 의미적 유사도를 계산하기 어렵다.

###  DTM (Document-Term Matrix)

단어 등장 횟수를 기반으로 벡터화하는 방법이다.

-   단어 순서를 고려하지 않는다.
-   Vocabulary Size가 중요하다.
-   문서 간 유사도 계산이 가능하다.

###  TF-IDF

TF(단어 빈도) × IDF(역문서 빈도)

모든 문서에 등장하는 단어는 중요도가 낮고, 특정 문서에만 자주 등장하는
단어는 중요도가 높다.

IDF에 로그를 사용하는 이유는 값이 기하급수적으로 커지는 것을 방지하기
위해서이다.

같은 단어라도 문서에 따라 TF-IDF 값은 달라진다.

현재 현업에서도 많이 사용된다.

##  Language Model

언어 모델은 다음에 올 단어의 확률을 계산하는 모델이다.

예: 나는 버스를 탔다\
나는 버스를 태운다

어떤 문장이 더 자연스러운지를 확률로 판단한다.

###  Statistical Language Model

데이터에서 단순히 단어를 카운트하여 확률을 계산하는 방식이다.

충분히 큰 데이터가 없으면 한계가 있다.

###  N-gram

연속된 n개의 단어 묶음이다.

-   n이 작으면 장기 의존성 문제가 발생한다.
-   n이 크면 데이터 부족 문제가 발생한다.

Bigram은 바로 이전 단어만 고려한다.

`<s>`{=html}, `</s>`{=html}는 문장 시작과 끝을 나타내는 토큰이다.

##  워드 임베딩

원-핫 인코딩의 한계를 보완하기 위해 등장하였다.

-   실수 벡터를 사용한다.
-   의미 정보를 반영할 수 있다.
-   벡터 간 유사도 계산이 가능하다.
