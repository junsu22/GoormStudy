# 텍스트 분류 모델 4종 비교 실습: NaiveBayes, LSTM, GRU, Word2Vec

## 개요

이번 포스팅에서는 텍스트 분류 및 단어 임베딩 문제를 네 가지 모델로 접근한 실습 내용을 정리합니다.
나이브 베이즈, LSTM, GRU, Word2Vec 각각의 특징과 실제 성능 결과를 비교합니다.

---

## 1. 나이브 베이즈 분류기 — 20 Newsgroups

### 개념

확률 기반 분류 알고리즘으로, 각 피처(단어)가 서로 **독립적**이라는 가정(naive) 하에 베이즈 정리를 적용합니다.
구조가 단순하지만 텍스트 분류에서 의외로 강력한 성능을 보입니다.

### 데이터

- **20 Newsgroups**: 20개 카테고리의 뉴스 기사 11,314건
- 카테고리 예시: `rec.autos`, `sci.space`, `talk.politics.guns` 등

### 전처리 파이프라인

```
텍스트 → CountVectorizer (DTM) → TfidfTransformer (TF-IDF) → MultinomialNB
```

- **CountVectorizer**: 단어 빈도 기반 문서-단어 행렬 생성 (11,314 × 130,107)
- **TF-IDF**: 자주 등장하지만 흔하지 않은 단어에 높은 가중치 부여

### 결과

| 항목 | 값 |
|---|---|
| 테스트 정확도 | **77.39%** |
| 학습 속도 | 매우 빠름 |
| 모델 복잡도 | 낮음 |

---

## 2. LSTM — 로이터 뉴스 46개 카테고리 분류

### 개념

LSTM(Long Short-Term Memory)은 RNN의 장기 의존성 문제를 해결한 모델입니다.
문장의 순서 정보를 기억하며 텍스트를 처리합니다.

### 데이터

- **Reuters**: 46개 카테고리 뉴스 데이터
- 상위 10,000개 단어 사용, 최대 길이 100으로 패딩

### 모델 구조

```
Embedding(10000, 128) → LSTM(128) → Dense(46, softmax)
```

### 학습 설정

- Optimizer: Adam
- Loss: sparse_categorical_crossentropy
- EarlyStopping(patience=4), ModelCheckpoint

### 결과

| Epoch | Train Acc | Val Acc |
|---|---|---|
| 1 | 32.7% | 48.4% |
| 10 | 80.5% | 67.2% |
| 17 (조기종료) | 91.4% | **70.2%** |

---

## 3. GRU — IMDB 영화 리뷰 감성 분류

### 개념

GRU(Gated Recurrent Unit)는 LSTM을 경량화한 모델입니다.
Reset Gate와 Update Gate 두 가지만 사용해 LSTM보다 파라미터가 적으면서도 유사한 성능을 냅니다.

### 데이터

- **IMDB**: 영화 리뷰 긍정/부정 이진 분류
- 상위 10,000개 단어, 최대 길이 500으로 패딩

### 모델 구조

```
Embedding(10000, 100) → GRU(128) → Dense(1, sigmoid)
```

### 학습 설정

- Optimizer: RMSprop
- Loss: binary_crossentropy
- EarlyStopping(patience=4), ModelCheckpoint

### 결과

| Epoch | Train Acc | Val Acc |
|---|---|---|
| 1 | 69.3% | 78.5% |
| 3 | 86.9% | 87.0% |
| 8 | 94.7% | **89.4%** |
| 12 (조기종료) | 98.2% | 86.9% |

- **테스트 정확도: 89.07%**

### 실제 예측 테스트

```
부정 리뷰 입력 → 99.09% 확률로 부정
긍정 리뷰 입력 → 99.30% 확률로 긍정
```

## 4. Word2Vec — 한국어 위키피디아 단어 임베딩

### 개념

Word2Vec은 단어를 고차원 벡터 공간에 매핑하는 임베딩 모델입니다.
의미적으로 유사한 단어들은 벡터 공간에서 가까운 위치에 놓이게 됩니다.

- **CBOW**: 주변 단어로 중심 단어 예측 (sg=0)
- **Skip-gram**: 중심 단어로 주변 단어 예측 (sg=1)

### 데이터

- **한국어 위키피디아 덤프** (1.2GB, 약 160만 기사)
- wikiextractor로 파싱 → 1,354개 파일, 총 13,263,501줄
- RAM 한계(12.7GB)로 인해 20만 줄 샘플 사용

### 전처리 파이프라인

```
위키 덤프(.bz2) → wikiextractor 파싱 → 파일 병합
→ MeCab 형태소 분석 → Word2Vec 학습
```

### 모델 설정

```python
Word2Vec(result, vector_size=100, window=5, min_count=5, workers=4, sg=0)
```

| 파라미터 | 값 | 설명 |
|---|---|---|
| vector_size | 100 | 임베딩 벡터 차원 |
| window | 5 | 문맥 윈도우 크기 |
| min_count | 5 | 최소 등장 빈도 |
| sg | 0 | CBOW 방식 |

### 유사 단어 결과

**대한민국** 유사 단어:
```
한국(0.765), 연방(0.730), 미국(0.714), 일본(0.705), 법원(0.700) ...
```

**반도체** 유사 단어:
```
태블릿(0.852), 제논(0.842), 휴대폰(0.834), 엔지니어링(0.829) ...
```

> **어벤져스**는 20만 줄 샘플에 등장하지 않아 `KeyError` 발생.
> 전체 데이터를 사용하면 어휘 커버리지가 높아짐.

### 트러블슈팅 기록

| 문제 | 원인 | 해결 |
|---|---|---|
| `No module 'MeCab'` | pip 설치 누락 | `pip install python-mecab-ko` |
| `mecabrc not found` | 설정 파일 부재 | `/usr/local/etc/mecabrc` 생성 |
| RAM 초과 (12.7GB) | 전체 데이터 처리 불가 | 20만 줄로 제한 |
| 런타임 끊김 | Colab 유휴 감지 | 브라우저 콘솔 자동 클릭 적용 |

## 정리

- **나이브 베이즈**: 빠르고 간단, 베이스라인 모델로 적합
- **LSTM**: 긴 문장의 문맥을 잘 파악, 다중 분류에 적합
- **GRU**: LSTM보다 학습 빠르고 이진 분류에서 높은 성능
- **Word2Vec**: 분류 모델이 아닌 임베딩 모델, 다른 NLP 모델의 전처리 단계로 활용 가능

> 단순한 분류 문제라면 나이브 베이즈로 시작하고, 문맥이 중요한 복잡한 문제라면 GRU/LSTM을 고려하는 것이 좋습니다.
> Word2Vec으로 학습된 임베딩은 GRU/LSTM의 Embedding 레이어 초기값으로 활용하면 성능 향상을 기대할 수 있습니다.
